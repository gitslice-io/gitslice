# Gitslice Core API

This document specifies the native `gitslice.core.v1` API surface served by
`cmd/gitslice-server` (`server/server.go`, `server/connect.go`). The canonical
protobuf source of truth lives in [`../proto/core/v1/`](../proto/core/v1/)
(shared types `Empty`, `SliceRef`, `EntryKind`, `TreeEntry`, and
`ActorAttribution` are in `common.proto`).

## 1. Transport, ConnectRPC Mapping & Auxiliary HTTP Routes

`gitslice-server` multiplexes HTTP/2 `h2c` gRPC and HTTP/1.1+HTTP/2 on a single
listener (with optional dedicated `HTTPAddr` and `GitHTTPAddr` listeners):

- **gRPC**: all 13 services in `gitslice.core.v1` plus standard
  `grpc.health.v1.Health` are registered in `newPrincipalGRPCServer`
  (`server/server.go`), with gzip compression enabled and a 128 MiB unary
  message cap (`rpclimits.MaxUnaryMessageBytes`).
- **ConnectRPC HTTP**: `server/connect.go` mounts generated ConnectRPC adapters
  (`server/connect_adapters_gen.go`, generated by `server/internal/connectgen`)
  for all 13 services at `/gitslice.core.v1.<Service>/<Method>`. Browsers
  (`web/` via `@connectrpc/connect-web`) and Cloudflare Workers talk directly to
  ConnectRPC without `grpc-gateway`.
- **Unary vs. streaming HTTP deadlines**: unary HTTP requests have bounded read
  (30s) and write (60s) deadlines. Streaming procedures (`streamingProcedures` in
  `server/connect_adapters_gen.go`), `/git/`, `application/grpc`,
  `application/connect+`, and `text/event-stream` requests bypass unary
  read/write deadlines.
- **Auxiliary HTTP routes** (`server/gateway.go`, `server/connect.go`):
  - `/git/` — Git Smart HTTP gateway (`internal/gitcompat`)
  - `/avatars/` — public account avatar images (`server/avatar_image.go`)
  - `/og/` — anonymous social/OpenGraph preview images (`server/social_image.go`)
  - `/automation-archive` — per-run bearer-authenticated checkout archive for
    bash automations (`AutomationRunService.ServeArchiveHTTP`)
  - `/healthz`, `/readyz` — unauthenticated liveness/readiness probes
  - `/metrics` — Prometheus metrics (protected by `GITSLICE_METRICS_TOKEN`)

## 2. Authentication, Public Methods & Rate Limiting

### 2.1 Principal Resolution (`server/auth.go`, `server/connect.go`)

Requests authenticate via `Authorization: Bearer <token>` (Clerk JWT, CLI
session token, scoped API key, or service token). The server resolves a
`Principal` (with `SubjectID`, acting/controller attribution, and API key
scopes) and attaches it to context via `authctx.WithPrincipal`.

- **Public methods (`isPublicMethod` in `server/auth.go`)** bypass bearer
  principal resolution at the interceptor/middleware layer:
  - `/gitslice.core.v1.AuthService/StartCliLogin`
  - `/gitslice.core.v1.AuthService/PollCliLogin`
  - `/gitslice.core.v1.AuthService/RegisterAgent` (when
    `GITSLICE_AGENT_SIGNUP_ENABLED` is enabled; per-IP hourly rate-limited)
  - `/gitslice.core.v1.AutomationRunService/*` (authenticates via per-run
    `run_token` inside each request; protected by a failure rate limiter)
  - `/grpc.health.v1.Health/*`
- **Optional bearer auth**: for other RPCs, missing `Authorization` headers are
  permitted through the transport middleware so public-slice read RPCs can
  succeed anonymously; handlers call `requireSubject(ctx)` or `authz` checks to
  enforce authentication and slice/account permissions.

### 2.2 Rate Limiting & Request IDs

- Every request receives a unique `X-Request-Id` header and context value
  (`internal/requestid`).
- Pre-auth IP rate limiting (default 30 RPS / 60 burst on HTTP) and per-subject
  rate limiting (default 500 RPS / 1000 burst) reject excess traffic with
  `RESOURCE_EXHAUSTED`.

## 3. Registered Services (All 13 Services)

All RPCs are **unary** unless explicitly marked `[server-stream]`,
`[client-stream]`, or `[bidi-stream]`. Exactly 7 RPCs across the API are
streaming (matching `streamingProcedures` in `server/connect_adapters_gen.go`).

### 3.1 `AuthService` (`proto/core/v1/auth.proto`)
Authentication, CLI login, agent registration/claim, API keys, organizations,
memberships, invitations, profiles, and account groups:

- CLI login & status: `StartCliLogin`, `PollCliLogin`, `CompleteCliLogin`,
  `GetAuthStatus`
- Usernames: `CheckUsernameAvailable`, `ChooseUsername`
- Agents & claims: `RegisterAgent`, `CreateDelegatedAgent`,
  `ListPendingClaims`, `AcceptClaim`, `ListOwnedAgents`
- Scoped API keys: `ListApiKeys`, `CreateApiKey`, `RevokeApiKey`
- Organizations & members: `CreateOrganization`, `ListAccountMembers`,
  `SetAccountMember`, `RemoveAccountMember`, `InviteAccountMember`,
  `ListAccountInvitations`, `ListMyInvitations`, `RespondToInvitation`,
  `CancelAccountInvitation`
- Profiles & avatars: `GetAccountProfile`, `UpdateAccountProfile`,
  `SetAccountAvatar`
- Account groups (`@account/group`): `CreateGroup`, `GetGroup`, `ListGroups`,
  `DeleteGroup`, `AddGroupMember`, `RemoveGroupMember`

### 3.2 `RepositoryService` (`proto/core/v1/repository.proto`)
Read-only source graph inspection, checkout, blame, history, and Git import:

- Tree & file reads: `ResolvePath`, `ListDirectory`, `ReadFile`, `RenderFile`,
  `ReadFiles`, `Checkout` `[server-stream]`
- Commits & refs: `GetCommit` (exact full `sha256:<64hex>` lookup),
  `ResolveCommit` (abbreviated prefix lookup, min 8 hex chars, scoped to
  caller's visible commits), `ListCommits` (paged history with optional `path`,
  `slice`, and `follow_moves`), `BlameFile`, `GetRef`
- Git repository import: `ImportGitRepository`,
  `ImportGitRepositoryStream` `[server-stream]`

### 3.3 `BlobService` (`proto/core/v1/blob.proto`)
Content-addressed blob presence checks, uploads, and streaming reads:

- `GetBlobStatus` (up to 1000 content hashes per call, scoped to slice access)
- `UploadBlob` (single unary upload), `UploadBlobs` (batch unary upload)
- `UploadBlobStream` `[client-stream]` (chunked streaming upload)
- `ReadBlobStream` `[server-stream]` (chunked streaming download)

### 3.4 `SliceService` (`proto/core/v1/slice.proto`)
Slice definitions, lifecycle, CI daemon pools, Git mirrors, tags, and members:

- Definitions: `CreateSlice`, `ResolveSlice`, `GetSlice`, `ListSlices`,
  `ListSliceDefinitionVersions`, `UpdateSliceDefinition`
- Lifecycle & settings: `DeleteSlice`, `RenameSlice`, `SetSliceArchived`,
  `SetSliceDescription`, `SetSliceMergeOnSubmit`
- CI daemon pools: `SetSliceCIDaemon`, `GetAccountCIDaemons`,
  `SetAccountCIDaemon`
- Legacy slice-secret bindings: `SetSliceSecret`, `DeleteSliceSecret`,
  `ListSliceSecrets` (superseded for general secret management by `SecretService`)
- Outbound Git mirrors: `GetSliceGitMirror`, `SetSliceGitMirror`,
  `DeleteSliceGitMirror`, `PushSliceGitMirror`
- Tags & members: `CreateTag`, `ListTags`, `ListSliceMembers`,
  `SetSliceMember`, `RemoveSliceMember`, `ListSharedSlices`

### 3.5 `WorkspaceService` (`proto/core/v1/workspace.proto`)
Backend helpers for native `gs` workspaces (local workspace state remains
client-owned; server validation is authoritative):

- `GetWorkspaceState`, `HydratePaths`, `ValidateWorkspaceDiff`,
  `RecordWorkspaceOperation`

### 3.6 `ChangesetService` (`proto/core/v1/changeset.proto`)
Primary write model — single-slice changesets, patchsets, review, submit,
collaboration, and advisory path intents:

- Core lifecycle: `CreateChangeset`, `GetChangeset`, `ListChangesets`,
  `DiffChangeset`, `UpdateChangeset`, `SubmitChangeset`, `AbandonChangeset`,
  `UpdateChangesetInfo`
- Review & checks: `ApproveChangeset`, `ReportCheckResult`
- Collaboration & multi-agent coordination: `AddChangesetCollaborator`,
  `RemoveChangesetCollaborator`, `HandoffChangeset`, `CreatePathIntent`,
  `ListPathIntents`, `DeletePathIntent`
- Server-side path ops: `CopyPath`, `MovePath`

### 3.7 `ChangesetStackService` (`proto/core/v1/changeset.proto`)
Ordered stacks of dependent changesets:

- `CreateStack`, `GetStack`, `ListStacks`, `AddStackEntry`, `MoveStackEntry`,
  `ReparentStackEntry`, `DetachStackEntry`, `Restack`, `SubmitStack`

### 3.8 `AgentService` (`proto/core/v1/agent.proto`)
BYO agent and CI daemon connectivity, slice exposure, and interactive agent
conversations:

- Daemon transport & management: `Connect` `[bidi-stream]`, `StandbyPoll`,
  `ListDaemons`, `RenameDaemon`, `ExposeDaemon`, `UnexposeDaemon`
- Conversations: `CreateConversation`, `ListConversations`, `GetConversation`,
  `SendAgentMessage`, `StreamConversation` `[server-stream]`,
  `GetConversationEvents`, `CloseConversation`

### 3.9 `CheckService` (`proto/core/v1/check.proto`)
CI check run inspection, reruns, live log streaming, and secret allowances:

- `ListCheckRuns`, `GetCheckRun`, `RerunCheck`,
  `StreamCheckRun` `[server-stream]`, `AllowPatchsetSecrets`

### 3.10 `SecretService` (`proto/core/v1/secret.proto`)
Encrypted account secrets scoped to slices and path prefixes:

- `ListSecrets`, `GetSecret`, `CreateSecret`, `UpdateSecret`, `DeleteSecret`,
  `RevealSecrets`, `RevealSliceSecrets`

### 3.11 `FeedbackService` (`proto/core/v1/feedback.proto`)
In-product feedback collection and operator triage:

- `SubmitFeedback`, `ListFeedback`, `ResolveFeedback`

### 3.12 `AutomationService` (`proto/core/v1/automation.proto`)
Folder policy inspection and `.gitslice/automations.yaml` run management:

- `GetFolderPolicy`, `ListAutomations`, `ListAutomationRuns`,
  `GetAutomationRun`, `ListAutomationRunLogs`, `RunAutomation`,
  `RerunAutomationRun`, `CancelAutomationRun`, `InspectAutomationTemplate`

### 3.13 `AutomationRunService` (`proto/core/v1/automation.proto`)
Run-token-authenticated callbacks used by `trigger-dispatch/` Dynamic Workers
and `BashRunner` containers (`gs-exec`) during an active automation run:

- Run lifecycle & logging: `StartRun`, `StartCallback`, `FinishRun`,
  `AppendRunLog`, `GetRunState`, `SetRunState`, `SetRunDetailsUrl`,
  `SetRunOutput`
- Scoped check & repo access: `CreateCheck`, `UpdateCheck`, `ReadFile`,
  `ListDirectory`, `GetChangeset`

## 4. Error And Pagination Conventions

### 4.1 Error Mapping

All services return standard gRPC status codes, which `server/connect.go` maps
1:1 to ConnectRPC error codes (`connectError`):

- `INVALID_ARGUMENT`: malformed path, invalid handle/prefix, missing required
  field, or request exceeding batch/size limits.
- `UNAUTHENTICATED`: missing or invalid bearer/run token.
- `PERMISSION_DENIED`: caller lacks required account/slice role, API key scope,
  or path visibility.
- `NOT_FOUND`: missing commit, path, slice, changeset, blob, or run (also used
  when hiding unauthorized private resources).
- `FAILED_PRECONDITION`: unsatisfied submit requirements, missing approvals or
  required checks, stale slice definition hash, or invalid state transition.
- `ABORTED`: optimistic concurrency conflict (path-head CAS mismatch, ref CAS
  conflict, or concurrent mutation).
- `RESOURCE_EXHAUSTED`: per-IP, per-subject, signup, or trigger-failure rate
  limit exceeded.

### 4.2 Pagination & Timestamps

- List endpoints use opaque cursor/token pagination (`cursor` / `next_cursor` or
  `page_token` / `next_page_token`) derived from stable sort keys (for example
  `(committed_at, commit_id)` in `ListCommits`).
- Proto timestamp fields use RFC 3339 UTC strings (`string`) across
  `gitslice.core.v1` messages for uniform JSON/ConnectRPC serialization.
- Direct commit creation is intentionally **not** exposed on the public API;
  commits are created only internally by the 3-stage publish pipeline and
  resumable Git import.
